1. Milleks see vajalik on?

Peaaegu igal meie andmebaasitabelil on kaks veergu:

  • created_at: millal rida loodi. Seda ei muudeta enam kunagi.
  • updated_at: millal rida viimati muudeti. See uueneb iga muudatusega.

Mõlemad on NOT NULL, seega peab keegi need alati täitma. Varem tegime seda iga kord käsitsi:

Instant now = Instant.now();
training.setCreatedAt(now);
training.setUpdatedAt(now);

Kolm rida pole palju. Mure on selles, et neid on vaja igas kohas, kus midagi luuakse või muudetakse. Kui üks arendaja unustab setUpdatedAt() muutmise teenusesse panna, ei anna keegi viga. Andmebaasis on lihtsalt vale kuupäev ja seda märgatakse alles kuude pärast.

Analoogia: postitempel. Kui saadad kirja, ei kirjuta sa ümbrikule ise kuupäeva. Postkontor lööb sinna templi, alati ja automaatselt. Sa ei saa seda unustada ega valesti kirjutada. JPA Auditing on meie entiteetide postkontor: sina ainult salvestad, tempel lüüakse ise.

Teenusest kaob ajatemplite loogika täielikult. Teenus tegeleb ainult äriloogikaga.

@Getter
@Setter
@Entity
@EntityListeners(AuditingEntityListener.class)@Table(name = "training", schema = "bcs_koolitused")
public class Training {
    // ... teised väljad ...

    @NotNull
    @CreatedDate    @Column(name = "created_at", nullable = false, updatable = false)
    private Instant createdAt;

    @NotNull
    @LastModifiedDate    @Column(name = "updated_at", nullable = false)
    private Instant updatedAt;
}

3. Kolm osa, mis peavad koos olema

Auditing töötab ainult siis, kui kõik kolm osa on paigas. Kui üks puudub, jäävad väljad null-iks ja salvestamine kukub läbi.

@EnableJpaAuditing

JpaAuditingConfig.java, üks kord terve rakenduse peale

Pealüliti. Ütleb Springile, et auditeerimise masinavärk tuleb käivitada. Postkontori analoogias: postkontor on avatud.

@EntityListeners(...)

Iga entiteedi klassi peal

Kuulaja. Paneb entiteedile külge AuditingEntityListener-i, kes kuulab sündmusi "hakkan salvestama" ja "hakkan muutma". Analoogias: kiri viiakse postkontorisse, mitte ei visata lihtsalt kasti.

@CreatedDate / @LastModifiedDate

Konkreetse välja peal

Silt. Ütleb kuulajale, millisesse välja aeg kirjutada. Analoogias: ümbrikul on kast, kuhu tempel lüüakse.

Lisaks on createdAt väljal updatable = false. See on turvavöö: isegi kui keegi kogemata setCreatedAt(...) välja kutsub, ei lähe see väärtus UPDATE lausesse.

4. Mis salvestamisel tegelikult toimub

JPA (täpsemalt Hibernate) annab entiteedi elu jooksul märku kindlatest hetkedest. Neid nimetatakse elutsükli sündmusteks (lifecycle events). Meile olulised on kaks:

  • @PrePersist: vahetult enne, kui uus rida andmebaasi lisatakse (INSERT).
  • @PreUpdate: vahetult enne, kui olemasolevat rida muudetakse (UPDATE).
  TrainingService              Hibernate                 AuditingEntityListener       Andmebaas
        │                          │                              │                         │
        │ repository.save(t)       │                              │                         │
        │─────────────────────────>│                              │                         │
        │                          │ uus entiteet? → @PrePersist  │                         │
        │                          │─────────────────────────────>│                         │
        │                          │                              │ createdAt = now         │
        │                          │                              │ updatedAt = now         │
        │                          │<─────────────────────────────│                         │
        │                          │ @NotNull kontroll: OK        │                         │
        │                          │ INSERT INTO training (..., created_at, updated_at)      │
        │                          │───────────────────────────────────────────────────────>│
        │<─────────────────────────│                              │                         │

Muutmisel on sama pilt, ainult sündmus on @PreUpdate ja kuulaja seab ainult updatedAt. createdAt jääb puutumata.

Miks @NotNull ei anna viga, kuigi teenus välja ei täida? Sest kuulaja jõuab enne. Järjekord on: kõigepealt @PrePersist (tempel lüüakse), alles siis valideerimine ja INSERT.

6. Lõksud

Lõks 1: JPQL @Modifying päring mööda auditeerimist

Auditing töötab ainult siis, kui muudad entiteeti (save() või muudatus transaktsiooni sees). Kui kirjutad repositooriumisse otse UPDATE päringu, läheb see Hibernate'i entiteedi sündmustest mööda. Kuulaja ei saa sellest teada.

// ❌ updated_at jääb vanaks
@Modifying
@Query("UPDATE Training t SET t.status = :status WHERE t.id = :trainingId")
void updateTrainingStatus(String status, Integer trainingId);

// ✅ sellisel juhul sea updatedAt päringus endas
@Modifying
@Query("UPDATE Training t SET t.status = :status, t.updatedAt = CURRENT_TIMESTAMP WHERE t.id = :trainingId")
void updateTrainingStatus(String status, Integer trainingId);

Lõks 2: JPA Buddy / IntelliJ genereerib entiteedi ilma annotatsioonideta

Kui lood uue entiteedi andmebaasi tabelist, ei tea generaator auditeerimisest midagi. Pead @EntityListeners, @CreatedDate ja @LastModifiedDate ise lisama. Vastasel korral saad esimesel salvestusel vea createdAt: must not be null. Kasuta allpool olevat checklisti.

Lõks 3: "Aga ma tahan ise aja panna"

Näiteks testandmete jaoks. @CreatedDate kirjutab uuel entiteedil sinu väärtuse üle. Kui tõesti on vaja kindlat kuupäeva, lisa see SQL-iga (3_import.sql). Tavakoodis ära proovi seda Java kaudu teha.

@LastModifiedDateVäli saab väärtuse loomisel ja igal muutmisel.
